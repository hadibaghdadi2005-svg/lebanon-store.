## What's been fixed (chronological)
1. **Fake login → real auth.** Removed the old "type any email/phone, no password, instantly logged in" system (which let anyone impersonate any customer, including the admin). Replaced with real Supabase Auth (email + password). `isAdminUser()` now checks a verified session email against `ADMIN_EMAIL`.
2. **Row Level Security was wide open.** Every table (`customers`, `orders`, `products`, `settings`) had RLS "enabled" but every policy was `true` for everyone — meaning direct API calls (bypassing the site entirely) could read/write anything. Locked down to: customers/orders scoped to their owner or admin; products/settings publicly readable but admin-only writable; storage bucket admin-only writable.
3. **Cost & supplier-link data was leaking everywhere** — hardcoded in the page's visible JS source, fully public in the `products` table, and embedded in every customer's own order history. Fixed by: stripping cost/supplier data from the JS source entirely, splitting `products` into an admin-only base table + a `products_public` view (safe columns only), and adding a database trigger that snapshots real cost server-side into an admin-only `order_item_costs` table at order time (the customer's browser never has access to cost data at any point).
4. **Session didn't persist across refresh** (always dropped back to login) — fixed by restoring the Supabase session on page load.
5. **Deleted orders didn't disappear for the customer live** — their realtime subscription only listened for status *updates*, not *deletes*. Added the missing handler + set `orders` to `REPLICA IDENTITY FULL` (needed for the delete filter to actually work).
6. **Misc correctness bugs:** order numbers had a hardcoded year (now dynamic), category/"View all" links did nothing (now real filtering), the shipping-fee consent modal described fake $/kg pricing (now matches the real flat per-governorate fee).
7. **Built a full mobile app UI** (imported from a Claude Design canvas project, "Lebanon Store App.dc.html") — a phone-width-only (<760px) experience with its own visual language (Caprasimo/Figtree/IBM Plex Mono fonts, terracotta palette), English-only, bottom tab bar navigation. Desktop site is untouched above 760px. All screens (home, product, cart, checkout, confirm, orders, tracking, account) are wired to the **real** backend — same cart/auth/checkout/orders as desktop, not mock data.
8. **Site defaulted to Arabic even on first load** — user wanted English-only site-wide. Fixed: English is now the default and only language (AR/EN toggle removed).
9. **Android bug: sign-up "Full name" field untappable.** Root cause: `.login-wrap` used `min-height:100vh` + `overflow:hidden`; `100vh` doesn't account for the mobile browser's address bar, so the sign-up form (taller than sign-in) could get clipped with no way to scroll to the hidden part. Fixed with `100dvh` + scrollable overflow, plus 16px input font-size and proper `autocomplete` attributes (both prevent related mobile-input quirks).
10. **Login "Full name" field only tappable at its far right edge, or not at all on some phones.** Root cause: `.login-wrap::after`, a large (480×480px) purely decorative background glow, had no `pointer-events:none` — it painted on top of the login card and silently ate taps over whatever part of the card it happened to overlap on a given screen size. Fixed by adding `pointer-events:none`.
11. **Removed the "Free delivery over $75" promo text** from the cart drawer footer and the mobile home banner (kept the real shipping-fee disclosure in the checkout consent modal, which is functional policy copy, not a promo blurb).
12. **Added an admin-editable home page billboard**, later upgraded (via a user-made Claude Design edit, see below) into a multi-slide carousel — image or video slides, each with its own title/subtitle/optional link (to a category or external URL) and button label, auto-rotating with dot navigation, editable from Admin → Settings, shown on both desktop and mobile home. Data lives in `settings.billboard_slides` (a JSON string column) plus a `billboard_enabled` toggle; six earlier single-slide columns (`billboard_title`, `billboard_image_url`, etc.) are still in the table but unused/superseded — safe to ignore or drop later.
13. **Fixed mobile "Deal of the week" silently defaulting to the catalog's first product** (an espresso machine) whenever nothing was marked Featured, instead of just showing nothing — `mHome()`'s `deal` used to fall back to `PRODUCTS[0]`, so unfeaturing the wrong item wouldn't actually remove it from that slot. Now it only shows an explicitly Featured product. Note: as of this fix, the catalog has only 2 active products (an espresso machine and headphones) and neither is currently marked Featured, so the desktop "Featured" section and mobile "Picked for you" section are intentionally empty until the user marks something Featured again.
14. **Merged a user-made Claude Design visual redesign** (uploaded as an exported HTML file) into `index.html`: rebrand to "HABIBI" (name, bag logo, "Everything, with love" tagline, "Shu 3ayez...." search placeholder, real contact info in the footer, demo-disclaimer line removed), plus the multi-slide billboard carousel from item 12. Workflow note for next time this happens: a Claude-Design export of this app is a full-file HTML export, not a diff — always diff it against the current `index.html` before replacing anything, check whether it still contains the real Supabase wiring (auth, RLS-safe queries, admin gating) rather than being a stale/mock snapshot, watch for orphaned functions the redesign leaves behind, check whether it expects any new database columns, and — importantly — check whether the admin has since entered real live content (e.g. via the admin panel) under the old data shape that needs migrating into any new shape before the redesign ships, or it'll silently get replaced by the design tool's placeholder content.
15. **Applied a second design-tool export** (this time provided as a downloaded file, not pasted): mobile billboard is now full-bleed/edge-to-edge instead of a margined card, the mobile header now fades and lifts slightly on scroll (mirrors the existing desktop hero fade effect), and the mobile search placeholder was brought in line with the desktop's "Shu 3ayez...." voice. Confirmed the workflow note from item 14 catches real issues in practice: a naive diff showed ~6,900 changed lines (turned out to be CRLF vs LF line-ending noise — normalize line endings before diffing), and the export also included two new functions (`handleBillboardImageUpload`, `removeBillboardImage`) that wrote to the old single-image billboard field superseded by item 12/14's multi-slide system and weren't wired to any button — left out as dead code.

## Working style notes
- User approves via short replies ("yes", "push it", "ok") — keep proposals concise, then act.
- Always confirm before `git push` and before any Supabase migration/schema change (the harness also force-prompts for DB migrations regardless).
- Test changes in a real browser (local static server + browser tools) before declaring done, including creating and cleaning up test accounts/orders in the live Supabase DB.
- Never handle the user's passwords, API keys, or SMTP credentials directly — point them to enter those themselves (in Supabase dashboard, email provider, etc.).
- User works across two PCs; sync is via `git push`/`git pull` only (no automatic sync). Keep this file updated at the end of a session so the other machine picks up full context on next `git pull`.
